# Ansible Role: Docker

The **`docker` role** automates the installation and configuration of Docker on Ubuntu hosts. It installs Docker Engine, the CLI, containerd, and the Docker Compose plugin, configures the official Docker APT repository, and manages Docker group membership for users defined in common user metadata.

The role is designed to be idempotent and suitable for homelab and production environments.

---

## Features

- **Docker Installation**
  - Installs prerequisite packages.
  - Configures Docker's official APT repository and signing key.
  - Installs Docker Engine, CLI, containerd, Buildx, and the Compose plugin.
  - Installs Python packages required for Docker-related Ansible modules and comparisons.
- **User Management**
  - Reads common user metadata from `/etc/ansible/common_users.yml`.
  - Adds users tagged with `docker` to the Docker group.
  - Preserves existing supplementary group memberships.
  - Ensures the Docker group exists.

---

## Requirements

- Supported platforms: Ubuntu 24.04 LTS (Noble) and Ubuntu 26.04 LTS (Resolute).
- Ansible 2.20 or later.
- Access to the Docker APT repository from target hosts.
- `/etc/ansible/common_users.yml` on target hosts when running user management.

## User Metadata

The user management tasks read `/etc/ansible/common_users.yml` from each target host. This file can be generated by the [common role](https://github.com/konkele/ansible-role-common).

Example:

```yaml
common_users:
  - name: alice
    tags:
      - docker
  - name: bob
    tags: []
```

Users with the `docker` tag are added to the Docker group. Users without the tag are not modified by this role's Docker group management tasks.

The metadata file must contain a top-level `common_users` list. Each user entry should include a `name` and may include a `tags` list.

**Important:** Membership in the Docker group grants privileges effectively equivalent to root access. Only grant this membership to trusted users.

---

## Dependencies

- No formal role dependencies.
- The [common role](https://github.com/konkele/ansible-role-common) can generate the user metadata consumed by this role.

The common role should run before Docker user management if it is responsible for creating `/etc/ansible/common_users.yml`.

---

## Tags

The role supports the following tags:

| Tag | Description |
|---|---|
| `docker` | Runs all Docker role tasks. |
| `docker_install` | Installs Docker and its prerequisites. |
| `docker_users` | Adds users tagged with `docker` to the Docker group. |

To install Docker without running user management, use the `docker_install` tag.

**Note:** The `docker_users` tasks expect `/etc/ansible/common_users.yml` to exist. They do not automatically skip when the file is missing.

## Example Playbook

```yaml
---
- name: Configure Docker hosts
  hosts: docker_hosts
  become: true
  roles:
    - role: docker
```

Run the complete role:

```bash
ansible-playbook -i inventory docker_playbook.yml
```

Install Docker only:

```bash
ansible-playbook -i inventory docker_playbook.yml --tags docker_install
```

Manage Docker group membership only:

```bash
ansible-playbook -i inventory docker_playbook.yml --tags docker_users
```

---

## Package Management

The role installs Docker packages using APT with `state: latest`. This ensures the latest versions available from the configured repository are installed when the role runs.

Review this behavior against your update policy if you prefer to control Docker upgrades separately.
